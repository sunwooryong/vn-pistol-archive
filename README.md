# 베트남 사격연맹 권총기록 아카이브

ISSF 권총 전 종목(10m/25m/50m, 국내·국제, 주니어·연령별)의 대회 기록을
베트남 사격연맹 공개 구글시트에서 수집·정규화하여 Supabase에 보관하고,
**종목·선수명으로 검색**할 수 있게 하는 파이프라인.

> 원본은 연맹이 운영하는 공개 구글시트 1개(CSV export). 사이트를 크롤링하지
> 않고 이 시트만 내려받아 처리한다. 요청은 실행당 1회.

## 무엇이 들어있나

- **대회 22개** (실데이터 기준): 국내 10 / 국제 12
- **성적 4,465행**, **시리즈 점수 23,979행**
- **선수 1,259명** (베트남 201 / 외국 1,058)
- 권총 종목 114개 표기 변형 → **6개 종목 × 성별 × 연령부**로 정규화 (미분류 0)

각 성적에 담기는 것: 대회·**대회기간**·장소, 종목, **경기 날짜/시각**, 선수(**성별**·생년월일·소속),
**본선 총점·시리즈별 점수·이너텐**, **결선 점수**, **메달**, **계산된 등위**(본선·결선·종합).

### 데이터에 대해 알아둘 점 (연도 커버리지)
- 시트에 실제 선수 결과가 있는 해는 **2024·2025·2026** 뿐. (+ 2015·2016 잔여 8행)
- **2017~2023년 실기록은 존재하지 않는다** (2022·2023은 일정표 껍데기, 이름·점수 없음).
  → "2020년부터"는 원본에 데이터가 없어 불가. 하한을 없애 존재하는 모든 실기록을 담는다.
- **2024년도 얇다**: 2024 국제대회는 일정만 있고, 실데이터는 11월 전국선수권 하나. **온전한 데이터는 2025년부터.**
- **결선 시리즈 점수는 원본에 없다.** 결선은 총점(Điểm K)만 기록. 본선은 시리즈 전부 있음.
- **등위는 원본에 없어 계산한다** (아래 규정 참조).

## 검색 UI

`web/` 는 별도 빌드 없이 도는 정적 페이지. 탭 네 개:
- **선수**: 이름 입력 → 성별·나이·소속 목록 → 선택 시 전 기록(메달 집계, 종목별 최고본선점수,
  대회기간·장소, 경기날짜, 종합등위·개인/단체메달, 본선/결선점수, 시리즈·이너텐).
- **대회별**: 연도·**국내/국제** 필터 → 대회 클릭 시 **바로 아래 인라인 펼침** → 종목탭 →
  **결선 결과(1~8위)** + 본선 순위표.
- **입상실적**: 연도·종목·국내외 필터 → **개인 메달 + 단체 메달**(팀 구성원·합계 포함).
- **랭킹**: 종목·성별·연령부별 **평균 본선점수 종합 랭킹**(선수 나이 표기).
- **이름 클릭**: 순위표·입상·랭킹 어디서든 선수 이름 → 전체 상세 모달.
- **우측 상단 ⓘ**: 데이터 기준일·출처, 등위=ISSF 6.15.1 계산값 안내, 완전성, 조회 건수.

라벨 표기: `10m 공기권총 남자부 U16`, `25m 스포츠권총 여자부 주니어`, `… 혼성단체부`.

데이터 소스는 `config.js` 의 `mode`:
- `auto`(기본): **localhost 는 `build/*.json` 미리보기**, 배포 도메인은 Supabase REST.
- DB 적재 전에도 로컬 미리보기로 화면 확인 가능.

```bash
# 로컬 미리보기 (DB 불필요, build/ 산출물 사용)
npm run etl                                   # build/*.json 먼저 생성
python -m http.server 8123 --directory .      # 프로젝트 루트에서
#  → http://localhost:8123/web/index.html
```

**배포**: `web/` 를 Netlify 등에 올리면 됨(기존 사이트와 동일 방식). 배포본은 Supabase 를
publishable 키로 읽으므로 **DB 적재(`npm run load`)가 먼저** 되어 있어야 한다.
읽기는 RLS `public_read` 로 SELECT 만 가능(안전).

## 사용법

```bash
npm install

# 1) 적재용 연결 문자열 (비밀번호 포함) — Supabase 대시보드 > Settings > Database
export DATABASE_URL="postgresql://postgres:<비밀번호>@db.<ref>.supabase.co:5432/postgres"

# 2) 스키마 적용 + 전량 적재 (한 번에)
npm run load

# 3) 일상 갱신 (스키마 유지, 데이터만 새로)
npm run update            # = etl:fetch + load:data

# 개별 실행
npm run etl               # data/shooting.csv 로 레코드셋 생성 (DB 불필요)
npm run etl:fetch         # 구글시트에서 새로 받아 레코드셋 생성
npm run load              # schema.sql 적용 + build/*.json 적재
npm run load:data         # 스키마 유지, 데이터만 재적재
npm run lookup "Phạm Quang Huy"   # 선수 기록 조회
npm run classify          # 종목명 분류 검증
```

`npm run etl` 은 DB 없이도 돌아가며 `build/qa-report.txt` 에 품질 리포트를 남긴다.
먼저 이걸로 검증한 뒤 `load` 하는 것을 권장.

### 키 사용 구분 (중요)
- **적재(쓰기)**: `DATABASE_URL`(Postgres 직결, 비밀번호). publishable 키로는 RLS 때문에 불가.
- **읽기(검색 UI)**: `publishable`(anon) 키 + RLS `public_read` 정책으로 SELECT 만 허용.
  UI 에는 절대 비밀번호/서비스키를 넣지 말 것.

## 배포 (GitHub Pages + Actions, 노트북 불필요)

`.github/workflows/deploy.yml` 이 **30분마다** 구글시트를 읽어 권총 JSON을 만들고
GitHub Pages 에 배포한다. 노트북·서버 없이 폰에서 상시 접속 가능하고, 새 대회가 시트에
추가되면 다음 빌드에서 자동 반영된다. 하루 1회 압축 스냅샷을 커밋해 **git 이력이 아카이브**가 된다.

최초 1회 설정(코치 계정에서):
1. GitHub 에 저장소 생성(예 `vn-pistol-archive`) 후 이 프로젝트 푸시.
2. 저장소 **Settings → Pages → Source = "GitHub Actions"**.
3. **Settings → Actions → General → Workflow permissions = "Read and write"** (스냅샷 커밋용).
4. Actions 탭에서 워크플로우 1회 수동 실행(`Run workflow`) 또는 푸시 시 자동 실행.
5. 사이트 주소: `https://<사용자>.github.io/<저장소>/` — 폰 홈화면에 설치(PWA) 가능.

- 배포본은 `build/*.json`(권총만, 소용량)을 같은 도메인에서 읽는다(`web/data.js` 가 경로 자동판별).
- Supabase 는 이 방식에서 **선택**(쓰지 않아도 됨). 필요시 이중 백업으로만 활용.

### (구방식) 매일 자동 갱신
`npm run update` 를 스케줄러(cron, GitHub Actions 등)에 걸면 매일 시트를 받아 데이터만
재적재한다. 데이터가 작아 delete + reload 방식이 안전하고 단순하다.

## 설계 노트

### 선수 식별 (동일인 통합)
원본에 선수 고유번호가 일관되게 없어 다음으로 식별한다.
- **국내**: `정규화된 이름 + 출생연도` — 국내 선수는 ID(소속+성별+생년월일)가 거의 다 있어
  출생연도 결측이 200명 중 1명뿐. 같은 대회·종목에 동일 키 충돌 0건.
- **국제**: `정규화된 이름 + 국가` — 외국 선수는 출생연도 결측이 많다(로마자 표기).
- **통합 패스**: 같은 이름·국적 안에서 출생연도·성별이 호환(같거나 한쪽 결측)이면 병합.
  생년이 다른 동명이인은 각각 유지.
- **소속은 이력(`affiliations`)으로 분리** — 이적·국가대표 겸직(TQG)으로 소속이 바뀌어도
  기록이 끊기지 않는다. 소속 2개 이상 선수 41명 확인.
- 이름·성조 표기는 성조/`đ` 제거 후 소문자로 정규화해 비교.

### 등위 계산 — ISSF 규정 6.15.1
원본에 등위 컬럼이 없어(TT 컬럼은 등위가 아니라 사대번호) 계산한다.
- **본선**: 총점 내림차순, 동점 시 **전 종목(10m·25m·50m) 이너텐 우선** →
  마지막 시리즈부터 카운트백.
  - 근거: ISSF Rule Book 2026(2026-07-01 발효) 6.15.1 표제가 10m·25m·50m·300m을 모두
    포함하고 (a)에서 이너텐 개수를 1순위로 규정. 25m 표적도 이너텐 정의됨(6.3.4.4 속사 50mm,
    6.3.4.5 정밀 25mm). → `lib/rank.js` `INNER_TEN_FIRST` 전부 true.
  - 발별 데이터가 없어 카운트백에서 갈리지 않으면 공동순위.
- **결선**: 결선 점수(Điểm K) 내림차순.
- **종합(placement)**: **메달 > 결선순위 > 본선순위** 우선순위로 산정.
  연맹이 부여한 메달을 최우선 근거로 삼아, 결선 점수가 시트에 누락돼도 top3가 뒤집히지 않는다.
- **50m 권총·단체전은 결선 없음**(ISSF 6.11.9.8) — 본선 순위로 메달 결정.

### 정규화·정제 규칙
- 숫자는 유럽식 쉼표 소수점(`86,0` → `86.0`).
- 종목명 표기 오류 흡수: `tiêu/tiểu chuẩn`, `C.kết/C/kết` 등.
- **결선(`- C.kết`) 행 제외**: 선수 없는 일정표 행. 결선 점수는 본선 행에 이미 있음.
- **25m 절반(`1/2`,`2/2`) 행 제외**: 기본 행에 6시리즈 전부 있고 절반 행은 중복.
  (기본 행 없이 절반만 있는 실데이터가 있으면 QA에서 `★누락위험`으로 경고 — 현재 0건.)
- **VIE 이중등재 제거**: 국제대회에서 베트남 선수가 국가코드(VIE)+소속코드로 두 번
  등재되는 현상. 성적이 완전히 동일하고 짝에 국내 소속 행이 있을 때 VIE 행 제거(약 111행).
- **생년 타당성 필터(1940~2016)**: 국제대회 SINH 컬럼의 오염값(예 1524) 무시.
